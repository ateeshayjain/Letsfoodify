# UI/UX audit against Apple HIG — 26 Aug 2026

Scope: the shipping theme (`build/theme/foodify/`) as rendered — templates,
`style.css`, and the form markup the inc/ modules emit. The HIG's numeric bars
are the useful part for a mobile web store (most of this store's traffic will be
phones, many of them iPhones on Safari): **44pt minimum touch targets**, text
contrast (HIG defers to WCAG: 4.5:1 text, 3:1 large text and UI shapes),
legible minimum sizes, appropriate keyboards, predictable interactions, motion
respect. Every contrast figure below is **computed from the theme.json palette**,
not eyeballed.

Preview-only `fx-` styles are out of scope — they never ship.

---

## P0 — fails a hard bar on a shipping surface

### 1. The prep-step number chips are unreadable: **1.68:1**

`style.css` `.fd-prep__n` sets `color: flame-ink (#C4451A)` on
`background: flame (#F07040)` — dark orange on mid orange. Measured **1.68:1**
against a 4.5:1 requirement. The step numbers on "How you make it" — the PDP's
signature band, added in the design pass — are effectively invisible to anyone
with low contrast sensitivity, and muddy for everyone.

WP-03's own recorded lesson was *"small uppercase badge text on the flame wash
needs the deeper ink"* — the class of bug was known; this instance shipped
anyway. **Fix (measured):** `paper` text on `flame-deep` = **5.77:1** (keeps the
chip saturated, numeral clearly light), or `char` on `flame` = 4.85:1.

### 2. The checkout address chooser radios submit on `change` — a keyboard trap

`inc/address-book.php:683` — `onchange="this.form.submit()"`. With a keyboard,
moving between radio options with arrow keys **fires `change` on the first
keypress**, which submits the form and reloads the page. A keyboard user can
never reach the second saved address; a screen-reader user gets a full
navigation as a side effect of *browsing the options*. This is HIG
predictability and WCAG 3.2.2 ("On Input: changing a setting does not
automatically cause a change of context") failed outright — on the checkout, the
screen with the least tolerance for surprise.

The `<noscript>` "Use this address" button already in the markup is the correct
mechanism. **Fix:** make the button always visible and drop the auto-submit, or
replace navigation with in-place field updates. The current design treats the
reload as a convenience; for keyboard users it is a wall.

## P1 — real defects, one notch down

### 3. Body-size text on the kraft band: **3.97:1**

`mute (#7A736A)` on `kraft-pale (#F4EBDF)` — the prep-step **detail sentences**
and the account-claim note. This is reading text, not a caption, at 13–14px.
**Fix (measured):** `kraft-deep` on kraft-pale = **4.98:1** (stays warm), or
`char` = 12.16:1.

### 4. Badge text on the flame wash: **4.27:1**

`flame-ink` on `flame-wash` — just under the bar, and it is uppercase text at
12px, where contrast matters most. **Fix (measured):** `flame-deep` on
flame-wash = **5.10:1**. This is literally the pairing the WP-03 lesson named.

### 5. Sub-44px touch targets beside 44px ones

The address-card **verb buttons** got `min-height: 44px`; the interactive things
next to them did not:

- `.fd-secondary` — the **Edit** link on every address card and the **Details**
  button on every order row
- `.fd-address-choose__manage` — "Manage saved addresses" at checkout
- `.showcoupon` — "Enter it here" on the coupon line

All are plain links at 13px with no padding rule: real target height ≈ 20px.
HIG floor is 44×44pt. **Fix:** the existing `tapTarget` token +
`display: inline-flex; align-items: center` on all three.

### 6. The address-book form gives an alphabet keyboard for numbers

Checkout's phone and PIN fields set `inputmode="numeric"` (checkout-fields.php).
The **address-book form's** phone and PIN inputs are bare `type="text"` with
autocomplete only — on an iPhone that is a full QWERTY keyboard for a 10-digit
number, in the exact flow built so "a returning customer types nothing".
**Fix:** thread `inputmode` through the `$text` closure for `phone` and
`postcode`.

## P2 — worth fixing, not urgent

7. **No skip link.** Keyboard users tab through the full header nav on every
   page (WCAG 2.4.1). One visually-hidden-until-focused link before the header.
8. **Footer separator** `kraft-deep` on `char` = 2.44:1 — decorative `hr`, below
   the 3:1 non-text bar. If it is meant to be seen, lighten it (`kraft` on char
   = 4.80); if not, it can stay as texture.
9. **`confirm()` on address delete** — a blocking system dialog. It works and it
   is honest; HIG prefers an inline, undoable pattern. Fine until something
   better exists; never remove the confirmation without adding undo.
10. **`.fd-spec dt` drops to 12px on mobile** — label text below the ~14px
    comfortable floor. `sm` (13px) costs nothing.

## What passes — measured, not assumed

- **Body text 13.89:1** on page, 14.35:1 on cards; `char` on the kraft band
  12.16:1. The core reading experience is excellent.
- **16px input font** — deliberately at the size that stops iOS Safari's
  focus-zoom, with the comment saying so.
- **Type scale in rem throughout** → respects the user's browser/Dynamic Type
  text size. No px-locked body text anywhere.
- **`prefers-reduced-motion` honoured globally**, one rule, everything covered.
- **`:focus-visible` styled** with a 2px flame-ink outline (4.82:1 — passes as a
  UI indicator).
- **Checkout errors move focus** to the alert and then the invalid field (WP-06)
  — better than HIG's floor, most stores never do it.
- **Input borders 3.35:1** — pass the non-text bar; the WP-03 fix that
  brightened them from `line` (1.36:1) did its job.
- **One-page checkout, stripped chrome** — HIG's "reduce steps, remove
  distractions" done structurally, not cosmetically.
- **Review stars carry `aria-label`**; the free-shipping bar is a real
  `role="progressbar"` with values.
- **Nonced single-button forms** for destructive verbs — predictability and
  safety over link-styled actions.
- **No fixed bottom bars**, so `env(safe-area-inset-*)` is not currently needed —
  becomes required the day a sticky add-to-cart bar is added. Noted for then.

---

## Verdict

The foundations HIG cares most about — legible core text, honest feedback,
reduced-motion, focus management, one-thing-per-screen checkout — are genuinely
good, several beyond typical store practice. The failures cluster in one place:
**the warm-on-warm corner of the palette** (three of four contrast failures are
flame-family-on-flame-family or mute-on-kraft), plus **one interaction bug that
only a keyboard reveals**. All six P0/P1 items are one-session fixes; none needs
a design change, only token swaps and small markup edits — and the fixes above
are pre-measured so applying them is mechanical.

Findings not fixed in this commit, deliberately: an audit that fixes as it goes
cannot be reviewed. The fix wave is a separate change.
